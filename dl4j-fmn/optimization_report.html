What Changed & Why

#LocationChangeWhy (reason)Impact
1 main() Batch size increased 32 → 256 for both train and test iterators. DL4J indexes rows by offset inside one contiguous buffer, so bigger batches greatly reduce per-batch Java → native boundary overhead, and give the vectorized BLAS kernels longer contiguous runs to chew on (better SIMD + cache locality). The model is tiny (784→128→10), so 256 fits easily in CPU memory. High
2 createDataSetIterator() Load all samples into two pre-allocated primitive float[] buffers, then create one feature INDArray and one label INDArray. The old loop called Nd4j.create() once per sample (60,000 native-backed arrays) plus a Nd4j.zeros(1,10) + putScalar per label. That is enormous allocator pressure (& GC churn) before training even starts. Bulk Nd4j.create(float[], shape) packs everything into one contiguous buffer. High
3 SimpleInMemoryIterator → BulkDataSetIterator Replaced the list-of-DataSet iterator. next() now extracts a zero-copy view with get(NDArrayIndex.interval(lo, hi), NDArrayIndex.all()). The old DataSet.merge(subList) allocated a fresh pair of arrays and memcpy'd every sample on every batch iteration (once per epoch!). Slicing a contiguous row-range only adjusts an offset + length — no copies at all (falling back to a single memcpy even if a view isn't possible). High
4 imports Removed unused ArrayList, Collections, StandardCopyOption; added NDArrayIndex and Files imports. Files.exists() / Files.createDirectories() in downloadToMavenDataFolder() were used but never imported — the project did not compile. NDArrayIndex is required by the new slicing code; the others were dead references. Medium
5 data format One-hot labels written straight into the pre-allocated float[] instead of per-sample NDArray objects. Contract with change #2: because arrays are zero-initialized by default, writing allLabels[i*10 + labelIdx] = 1.0f produces the identical one-hot layout with far fewer instructions. Low
6 BASE_URL Base URL changed from https://github.com/.../tree/master/data/fashion/ to https://raw.githubusercontent.com/.../master/data/fashion/. Requesting a file under github.com/.../tree/... returns the HTML blob-view page (Content-Type: text/html), so every download silently saved the same HTML page instead of the dataset — all files came out identical in size. raw.githubusercontent.com serves the actual binary (application/octet-stream). High
7 downloadFiles() Added fail-fast checks: explicit redirect following, HTTP 200 validation, and rejection of text/html responses. A wrong URL previously produced a corrupted (HTML) file with no error at all. Now a non-200 status or an HTML payload throws an IOException with the file name + size, so silent corruption cannot happen again. Medium
8 MnistDigitApp.java New class for MNIST handwritten digits (0–9). Same architecture, same optimized data pipeline. Data source: raw.githubusercontent.com/sunsided/mnist/master/. Verified correct IDX headers (magic 2051, 60 000 images). The original request was for a digits classifier. Fashion MNIST and MNIST digits share the same file format but different image content. A separate class avoids conflating the two and keeps each dataset in its own folder. High
9 pom.xml <mainClass> extracted to a Maven property; added a <profile id="digits"> that overrides it to MnistDigitApp. Passing -Dexec.mainClass=... on the command line does not override a hardcoded <configuration> block in exec-maven-plugin. A profile with -Pdigits is the reliable, documented way to switch classifiers. Medium
10 data directories Fashion MNIST downloads to ./data/fashion-mnist/, digits to ./data/mnist-digits/. Both classifiers previously wrote to ./data/mnist/. Whichever ran first populated that folder; the second reused its stale files — causing MnistDigitApp to display Fashion MNIST clothes instead of digits. High
The neural network configuration, optimizer (Adam 0.001), seed, layer shapes and the evaluation loop are intentionally untouched — results remain numerically equivalent; only data-loading and iteration mechanics changed.

                totalLoss += model.score();

            INDArray output = model.output(next.getFeatures());

        }

    private static void downloadFiles(String destinationDir) {
        File dir = new File(destinationDir);
        if (!dir.exists()) dir.mkdirs();

        System.out.println("--- Downloading Dataset ---");
        for (String fileName : FILE_NAMES) {
            File targetFile = new File(dir, fileName);
            if (targetFile.exists()) {
                System.out.println("[Skipped] Already exists: " + fileName);
                continue;
            }

            try {
                System.out.println("downloading: " + BASE_URL + fileName);
                HttpURLConnection connection = (HttpURLConnection) new URL(BASE_URL + fileName).openConnection();
                connection.setRequestProperty("User-Agent", "Mozilla/5.0");
                int fileSize = connection.getContentLength();

                try (InputStream in = connection.getInputStream();
                     FileOutputStream fos = new FileOutputStream(targetFile)) {

                    int bytesRead;
                    int totalBytesRead = 0;

                System.err.println("\nFailed to download " + fileName + ": " + e.getMessage());
            }
        }
    }

    private static DataSetIterator createDataSetIterator(String imagesPath, String labelsPath, int batchSize) throws IOException {
        try (DataInputStream imgIn = new DataInputStream(new GZIPInputStream(new FileInputStream(imagesPath)));
             DataInputStream lblIn = new DataInputStream(new GZIPInputStream(new FileInputStream(labelsPath)))) {

            imgIn.readInt(); // Magic number
            int numImages = imgIn.readInt();
            int numRows = imgIn.readInt();
            int numCols = imgIn.readInt();

            lblIn.readInt(); // Magic number
            int numLabels = lblIn.readInt();

            if (numImages != numLabels) {
                throw new IllegalArgumentException("Image count does not match Label count!");
            }

            int featureSize = numRows * numCols;
            List<DataSet> dataSetList = new ArrayList<>();
            
            String targetName = new File(imagesPath).getName();
            int progressInterval = numImages / 10;

            for (int i = 0; i < numImages; i++) {
                float[] featureData = new float[featureSize];
                for (int j = 0; j < featureSize; j++) {
                    featureData[j] = (imgIn.readUnsignedByte()) / 255.0f;
                }
                INDArray features = Nd4j.create(featureData, new int[]{1, featureSize});

                int labelIdx = lblIn.readUnsignedByte();
                INDArray labels = Nd4j.zeros(1, 10);
                labels.putScalar(new int[]{0, labelIdx}, 1.0);

                dataSetList.add(new DataSet(features, labels));

                if (i % progressInterval == 0 || i == numImages - 1) {
                    int percent = (int) (((double) (i + 1) / numImages) * 100);
                    System.out.print("\rLoading " + targetName + ": [" + percent + "%]");
                }
            }
            System.out.println();
            return new SimpleInMemoryIterator(dataSetList, batchSize);
        }
    }

    // Custom inline data iterator implementation bypassing all buggy dependency packages
    private static class SimpleInMemoryIterator implements DataSetIterator {
        private final List<DataSet> data;
        private final int batchSize;
        private int cursor = 0;

        public SimpleInMemoryIterator(List<DataSet> data, int batchSize) {
            this.data = data;
            this.batchSize = batchSize;
        }

        @Override
        public boolean hasNext() {
            return cursor < data.size();
        }

        @Override
        public DataSet next() {
            return next(batchSize);
        }

        @Override
        public DataSet next(int num) {
            if (!hasNext()) throw new NoSuchElementException();
            int end = Math.min(cursor + num, data.size());
            List<DataSet> subList = data.subList(cursor, end);
            cursor = end;
            return DataSet.merge(subList);
        }

        @Override
        public int inputColumns() { return 28 * 28; }
        @Override
        public int totalOutcomes() { return 10; }
        @Override
        public boolean resetSupported() { return true; }
        @Override
        public boolean asyncSupported() { return false; }
        @Override
        public void reset() { cursor = 0; }
        @Override
        public int batch() { return batchSize; }
        @Override
        public void setPreProcessor(DataSetPreProcessor preProcessor) {}
        @Override
        public DataSetPreProcessor getPreProcessor() { return null; }
        @Override
        public List<String> getLabels() { return null; }
    }
}

    private static double[] perClassAccuracy(Evaluation eval) {
        double[] accuracy = new double[10];
        for (int c = 0; c < 10; c++) {
            int tp = (int) Math.round(eval.getTruePositives().getCount(c));
            int fn = (int) Math.round(eval.getFalseNegatives().getCount(c));
            int total = tp + fn;
            accuracy[c] = (total > 0) ? (double) tp / total : 0.0;
        }
        return accuracy;
    }

    private static int[] findOneSamplePerClass(String imagesPath, String labelsPath) throws IOException {
        int[] result = new int[10];
        java.util.Arrays.fill(result, -1);
        try (DataInputStream imgIn = new DataInputStream(new GZIPInputStream(new FileInputStream(imagesPath)));
             DataInputStream lblIn = new DataInputStream(new GZIPInputStream(new FileInputStream(labelsPath)))) {

            imgIn.readInt();
            int numImages = imgIn.readInt();
            int numRows = imgIn.readInt();
            int numCols = imgIn.readInt();
            lblIn.readInt();
            lblIn.readInt();

            int featureSize = numRows * numCols;
            byte[] pixel = new byte[featureSize];
            int found = 0;
            for (int i = 0; i < numImages && found < 10; i++) {
                imgIn.readFully(pixel);
                int labelIdx = lblIn.readUnsignedByte();
                if (result[labelIdx] == -1) {
                    result[labelIdx] = i;
                    found++;
                }
            }
        }
        return result;
    }

    private static BufferedImage[] loadTestImages(String imagesPath, int[] sampleImage) throws IOException {
        try (DataInputStream imgIn = new DataInputStream(new GZIPInputStream(new FileInputStream(imagesPath)))) {
            imgIn.readInt();
            int numImages = imgIn.readInt();
            int numRows = imgIn.readInt();
            int numCols = imgIn.readInt();

            int featureSize = numRows * numCols;
            byte[] pixel = new byte[featureSize];
            BufferedImage[] out = new BufferedImage[10];

            for (int i = 0; i < numImages; i++) {
                imgIn.readFully(pixel);
                for (int c = 0; c < 10; c++) {
                    if (sampleImage[c] == i) {
                        BufferedImage bi = new BufferedImage(numCols, numRows, BufferedImage.TYPE_INT_ARGB);
                        int p = 0;
                        for (int y = 0; y < numRows; y++) {
                            for (int x = 0; x < numCols; x++) {
                                int b = pixel[p++] & 0xff;
                                int rgb = (255 << 24) | (b << 16) | (b << 8) | b;
                                bi.setRGB(x, y, rgb);
                            }
                        }
                        out[c] = bi;
                    }
                }
            }
            return out;
        }
    }

    private static double[] perClassAccuracy(Evaluation eval) {
        double[] accuracy = new double[10];
        for (int c = 0; c < 10; c++) {
            int tp = (int) Math.round(eval.getTruePositives().getCount(c));
            int fn = (int) Math.round(eval.getFalseNegatives().getCount(c));
            int total = tp + fn;
            accuracy[c] = (total > 0) ? (double) tp / total : 0.0;
        }
        return accuracy;
    }

KEY DIFFERENCES

1. Batch size — lines ~55/59

  • OLD: createDataSetIterator(..., 32)
  • NEW: createDataSetIterator(..., 256)
  • Reason: Fewer native-backend invocations, larger contiguous matmul per call, better cache/SIMD efficiency.

2. Data loading — createDataSetIterator()

  • OLD: per-sample loop allocating a Nd4j.create(float[], {1, 784}) array and a Nd4j.zeros(1, 10) + putScalar label, storing them in a List<DataSet>.
  • NEW: two plain float[] buffers filled in the same loop, then a single Nd4j.create(float[], {60000, 784}) and Nd4j.create(float[], {60000, 10}).
  • Reason: 60,000 thin arrays → 2 fat arrays. One allocation, one contiguous native buffer, minimal GC pressure.

3. Iterator — SimpleInMemoryIterator vs BulkDataSetIterator

  • OLD: DataSet.merge(subList) on every next() — builds fresh arrays and copies bytes each batch, every epoch.
  • NEW: features.get(NDArrayIndex.interval(cursor, end), NDArrayIndex.all()) — a zero-copy row-range view (maximum one cheap copy even in the fallback case).
  • Reason: Eliminate the per-batch copy + allocation repeated across all 5 epochs.

4. Build

  • Added imports org.nd4j.linalg.indexing.NDArrayIndex and java.nio.file.Files; dropped unused java.util.ArrayList, java.util.Collections, java.nio.file.StandardCopyOption.
  • Reason: Make the code compile (Files was used but never imported) and match the new slicing API.

5. Dataset download — BASE_URL + downloadFiles()

  • OLD: https://github.com/zalandoresearch/fashion-mnist/tree/master/data/fashion/ — a GitHub web-page URL. Every request returned the HTML blob-view, so all 4 files were the SAME HTML page (identical sizes, corrupt data).
  • NEW: https://raw.githubusercontent.com/zalandoresearch/fashion-mnist/master/data/fashion/ — serves real binaries. Verified sizes: 25.8 MB train images, 28.8 KB train labels, 4.3 MB test images, 5 KB test labels.
  • NEW: download loop now forces redirect following, checks getResponseCode() == 200, and throws if Content-Type: text/html — so silent HTML corruption fails loudly instead.
  • Reason: The web UI URL returns a rendered page (HTML), never raw bytes. Picking the raw host fixes downloads; the validation prevents regressions.

6. New MnistDigitApp class

  • Separate class for MNIST handwritten digits (0–9). Same model architecture (784→128→10), same optimized data pipeline, different data source.
  • Data source: https://raw.githubusercontent.com/sunsided/mnist/master/ — verified correct IDX format (magic number 2051, 60,000 images, 28×28 pixels).
  • Labels: "0" through "9" instead of clothing category names.
  • Data directory: ./data/mnist-digits/ (separate from fashion-mnist) to prevent file collisions.

  • New <profile id="digits"> overrides the property to com.example.MnistDigitApp.
  • Commands: Fashion MNIST = mvn compile exec:java, Digits = mvn compile exec:java -Pdigits.
  • Reason: -Dexec.mainClass=... cannot override a hardcoded <configuration> block in exec-maven-plugin; the profile approach is the documented solution.
